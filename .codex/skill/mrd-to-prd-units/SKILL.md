# MRD 拆分为开发 PRD 单元

本 skill 用于把 MRD 拆分成后续能与开发、设计、测试协作的 PRD 单元。PRD 单元必须对应明确开发对象，例如页面、交互、服务、数据、接口、系统能力或可测试流程。

## 前置条件

执行前必须满足：

1. 用户明确调用 `$mrd-to-prd-units`，或明确要求使用本 skill。
2. 当前会话中可以明确识别 MRD 文件路径。

如果 MRD 文件路径无法识别，直接要求用户提供 MRD 文件路径。

如果 Graphiti MCP 可用，优先用 Graphiti 建立和检索需求图谱；如果不可用，可以基于 MRD 文本结构化拆分，但必须说明未使用 Graphiti，且不得伪造 Graphiti group_id、节点或查询结果。

## 核心拆分原则

- 只拆需要开发交付的 PRD 单元。
- 不按 MRD 章节机械切分。
- 不把产品背景、目标用户、产品目标、非目标范围、版本规划、成功指标、纯技术栈建议拆成独立 PRD。
- 背景、目标、范围、非目标、指标只能作为相关 PRD 的上下文、边界、约束或验收口径出现。
- 每个 PRD 单元必须可独立理解、实现、测试和验收。
- 每个 PRD 单元必须有明确输入、输出、触发条件、用户动作、状态变化或接口契约。
- 共享实体、事件、配置、权限模型必须统一定义，避免在多个 PRD 中互相冲突。

## 文件命名规则

- 输出目录默认使用 MRD 同级 `prd/`，除非用户指定其他目录。
- 文件名除序号、连接符和扩展名外，必须使用中文。
- 推荐格式：`NN-中文功能名称.md`。
- 不使用英文 slug，例如不要生成 `prd-01-desktop-pet.md`。
- 索引和审查报告也使用中文命名，例如 `00-PRD单元索引.md`、`99-一致性审查.md`。

## 推荐产物结构

```text
prd/
  00-PRD单元索引.md
  01-桌宠入口与桌面交互.md
  02-剪贴板监听与内容归一化.md
  03-剪贴板历史栈与本地存储.md
  99-一致性审查.md
```

## 工作流

1. 读取 `references/prd-template.md`。
2. 读取 MRD，提取目标、用户、核心场景、功能、流程、模块、事件、数据实体、配置、权限、技术约束和版本边界。
3. 识别开发 PRD 候选单元。候选单元必须对应可交付能力，而不是管理性说明。
4. 删除非开发候选单元，把其中有价值的信息并入相关开发 PRD 的背景、范围、约束或验收标准。
5. 为每个 PRD 单元梳理上游依赖、下游影响、共享实体、事件、接口、状态和验收标准。
6. 按中文文件名生成 PRD 单元。
7. 生成 `00-PRD单元索引.md`，索引必须说明每个单元为何是开发单元及其依赖。
8. 读取 `references/consistency-review-rubric.md`，生成 `99-一致性审查.md`。

## PRD 单元判定标准

可以拆成 PRD：

- 需要新增或修改用户界面。
- 需要新增或修改用户交互。
- 需要新增或修改后端、原生、存储、事件、权限、打包或系统能力。
- 需要定义数据实体、接口、状态流转或错误处理。
- 可以写出可测试验收标准。

不要拆成 PRD：

- 只描述项目背景、目标用户、产品目标或非目标。
- 只描述版本计划或成功指标。
- 只描述技术栈建议，且不对应具体架构或工程能力。
- 只做说明文档，不产生开发任务。

## 索引要求

索引至少包含：

```markdown
| 序号 | PRD 单元 | 是否开发单元 | 核心交付 | 上游依赖 | 下游影响 | 共享实体 | 状态 |
|---|---|---|---|---|---|---|---|
```

索引中可加入“全局背景摘要”，但不要生成独立的“产品基础与范围”PRD。

## 硬性规则

- 没有可识别的 MRD 文件路径，不执行。
- 不生成非开发 PRD 单元。
- 不生成无法独立验收的 PRD 单元。
- 不生成英文 slug 文件名。
- 不把跨模块共享实体复制成多个互相独立的定义。
- 不伪造 Graphiti 输出。
