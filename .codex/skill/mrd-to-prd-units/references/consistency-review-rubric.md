# 一致性审查标准

用于审查 MRD 拆分后的开发 PRD 单元是否覆盖核心开发需求、依赖清晰且粒度合理。

## 审查输入

- MRD 文件或 MRD 摘要。
- `00-PRD单元索引.md`。
- 所有 `NN-*.md` PRD 单元。
- Graphiti 导出的关键节点和关系摘要，若可用。

## 审查维度

### 1. MRD 功能覆盖

- 明确需要开发的功能是否被覆盖。
- 关键流程、用例、模块、事件、数据实体、配置、权限是否有对应 PRD 或被合理并入。
- 是否遗漏影响 MVP 闭环的开发内容。

### 2. 非开发单元过滤

- 是否错误生成“产品基础”“背景范围”“目标用户”“产品目标”“版本规划”“成功指标”等非开发 PRD。
- 背景、目标、范围、非目标是否只作为相关 PRD 的上下文、边界、约束或验收口径出现。

### 3. 粒度与可验收性

- 是否存在过粗的 PRD，导致实现和验收风险过高。
- 是否存在过细但无法独立验收的 PRD。
- 每个 PRD 是否对应页面、交互、服务、数据、接口、系统能力或可测试流程。
- 每个 PRD 是否有明确验收标准。

### 4. 依赖与共享实体

- 上游依赖是否清晰。
- 下游影响是否清晰。
- 共享实体、事件、配置、权限模型是否统一。
- 是否存在依赖断点或未标记的循环依赖。

### 5. 流程完整性

- MVP 用户闭环是否能串起来：桌宠入口、监听、存储、面板、恢复、暂停、清空、隐私告知。
- 异常流程是否被覆盖。

### 6. 技术与隐私约束

- 是否遵守 MRD 中的本地优先、隐私授权、事件驱动、Windows/Tauri/React/Rust/SQLite 等约束。
- 是否有 Agent 后续能力的必要预留，但没有过度实现。

### 7. 文件命名

- 文件名除序号外是否使用中文。
- 是否存在英文 slug 文件名。

## 输出格式

```markdown
# 一致性审查

## 总体结论

- 结论: pass / pass-with-issues / fail
- 主要风险:
- 建议处理顺序:

## 发现的问题

| 严重级别 | 类型 | 涉及 PRD | 问题 | 建议 |
|---|---|---|---|---|

## 覆盖性检查

## 非开发单元过滤检查

## 依赖与共享实体检查

## 粒度与可验收性检查

## 技术与隐私约束检查

## 文件命名检查

## 建议调整后的 PRD 列表
```

严重级别：

- `P0`: 会导致最终产品无法满足 MRD 核心目标。
- `P1`: 会导致关键流程、关键依赖或关键实体断裂。
- `P2`: 会影响实现质量、验收清晰度或维护成本。
- `P3`: 表述、格式、命名、轻微重复或局部清晰度问题。
