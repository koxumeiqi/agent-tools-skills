# 一致性审查标准

本文件用于子 Agent 独立审查 MRD 拆分后的 PRD 单元。

## 审查目标

判断拆分结果是否在不丢失全局目标、不破坏依赖关系、不制造孤立 PRD 的前提下，将大型 MRD 拆成了可实现、可验收、可追踪的 PRD 单元。

## 输入

审查 Agent 只能使用：

- MRD 文件或 MRD 摘要。
- `00-global-intent.md`。
- `01-graph-namespace.md`。
- Graphiti 导出的关键节点和关系摘要。
- `02-prd-index.md`。
- 所有 `units/PRD-*.md`。

不要依赖主 Agent 的拆分过程说明或主观意图。

## 审查维度

### 1. MRD 覆盖完整性

- 是否所有明确功能需求都被覆盖。
- 是否所有关键流程、用例、模块、技术约束都有对应 PRD 或明确说明。
- 是否有 MRD 中的重要内容被遗漏。

### 2. 全局意图一致性

- 每个 PRD 是否服务至少一个项目目标、核心意图或核心场景。
- 是否存在脱离整体目标的 PRD。
- 是否有 PRD 的局部目标与整体目标冲突。

### 3. PRD 单元粒度

- 是否存在过粗的 PRD，导致实现和验收风险过高。
- 是否存在过细但无法独立验收的 PRD。
- 是否存在可以合并或必须继续拆分的单元。

### 4. 依赖与状态连续性

- 上游依赖是否清晰。
- 下游影响是否清晰。
- 是否存在依赖断点。
- 是否存在循环依赖但未标记。
- 是否存在 PRD 单元之间状态不一致。

### 5. 共享实体一致性

- 共享实体是否统一定义。
- 同一实体是否在多个 PRD 中出现冲突字段、状态或生命周期。
- 跨模块实体是否正确体现在索引和图谱摘要中。

### 6. 流程完整性

- 用户主流程是否可以从多个 PRD 串起来。
- 异常流程是否被覆盖。
- 关键业务闭环是否断裂。

### 7. 技术约束一致性

- PRD 是否遵守 MRD 中的技术栈、架构、集成、安全、性能约束。
- 是否有技术约束被遗漏或误用。

### 8. 可验收性

- 每个 PRD 是否有明确验收标准。
- 验收标准是否可测试、可观察。
- 是否存在只有愿景、没有可执行验收边界的 PRD。

### 9. 来源可追溯性

- 每个 PRD 是否能追溯到 MRD 来源片段或 Graphiti 节点关系。
- 是否有凭空新增的需求。
- 是否有来源不清但影响较大的假设。

## 输出格式

```markdown
# 一致性审查报告

## 总体结论

- 结论: pass / pass-with-issues / fail
- 主要风险:
- 建议处理顺序:

## 发现的问题

| 严重级别 | 类型 | 涉及 PRD | 问题 | 建议 |
|---|---|---|---|---|

## 覆盖性检查

## 全局意图一致性检查

## 依赖与共享实体检查

## 粒度检查

## 技术约束检查

## 可验收性检查

## 需要补充的问题

## 建议调整后的 PRD 列表
```

## 严重级别

- `P0`: 会导致最终产品无法满足 MRD 核心目标。
- `P1`: 会导致关键流程、关键依赖或关键实体断裂。
- `P2`: 会影响实现质量、验收清晰度或维护成本。
- `P3`: 表述、格式、轻微重复或局部清晰度问题。
